# 本地内容检索系统：五分钟项目演示成片脚本

## 一、成片目标

用一段 5 分钟、1920×1080、30 fps 的 Windows 桌面录屏，完整证明项目能在本机索引 TXT、PDF、DOCX、JPG、PNG 五种格式，并完成精确、文本语义和图像语义检索，以及筛选、复制路径、打开文件和无障碍设置。

能力边界必须如实说明：服务只监听 localhost；离线指运行时不上传文件、查询或片段，不等于首次安装时完全不需要网络，依赖和模型需预先准备。结果中的 score 不是概率，也不是准确率，只用于本次结果的相关性排序。图像语义结果可能因模型与运行环境发生排序波动，演示只验证目标文件出现在可见结果。

## 二、录制前准备

1. 将录屏画布固定为 **1920×1080、30 fps**，系统缩放先设为 100%。开启麦克风并试录一句，显示鼠标指针和单击效果；隐藏私密内容，关闭通知、聊天软件弹窗与任务栏预览。只保留终端、Flutter 窗口和装有五个样例的资源管理器。
2. 从仓库根目录打开 Windows PowerShell。所有缓存和临时内容放在 F 盘。首轮准备两个不同且全新的数据目录：`F:\contentretrieval-demo\rehearsal-01` 只用于两遍完整预演和异常离线片段预录，`F:\contentretrieval-demo\recording-01` 只用于正式录制。不得删除旧目录；重录改用新的 `rehearsal-02` 与 `recording-02`，避免索引状态串用。
3. 执行以下命令生成固定演示数据。首次生成不带 `--force`；命令使用锁定依赖，不安装额外包。

```powershell
Set-Location F:\contentretrivalsystem
New-Item -ItemType Directory -Force F:\contentretrieval-demo\temp | Out-Null
$env:TEMP = 'F:\contentretrieval-demo\temp'
$env:TMP = 'F:\contentretrieval-demo\temp'
$env:UV_CACHE_DIR = 'F:\contentretrieval-demo\uv-cache'
uv run --project tools/demo --locked python tools/demo/generate_demo_data.py F:\contentretrieval-demo\fixtures-01
```

4. 先为预演实例做 MVP 预检，再启动 `rehearsal-01`；也就是先运行 `tools/start-mvp.ps1 -CheckOnly`。`-CheckOnly` 通过后才启动，不要省略 `-DataDir`。

```powershell
& .\tools\start-mvp.ps1 -CheckOnly -DataDir 'F:\contentretrieval-demo\rehearsal-01'
& .\tools\start-mvp.ps1 -DataDir 'F:\contentretrieval-demo\rehearsal-01'
```

5. 在另一个 PowerShell 窗口确认 `http://127.0.0.1:8000/health/ready` 返回就绪，再启动 Flutter 桌面端。

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/ready
Set-Location F:\contentretrivalsystem\frontend
flutter run -d windows
```

6. 在 `rehearsal-01` 中用“添加资料文件夹”索引 `F:\contentretrieval-demo\fixtures-01`。确认五个文件均出现且状态为“资料已可搜索”。随后把五个文件、三类查询流程预演两遍：精确查询一次、文本语义查询两次、图像语义查询两次；每条查询都连续验证两次。
7. 在 `rehearsal-01` 中预录异常离线片段：按 `Ctrl+3` 进入设置，把服务地址改成 `http://127.0.0.1:65534` 并点“保存设置”；按 `Ctrl+2` 进入索引库，按 `F5` 刷新，录到“无法连接本地检索服务，请检查服务地址和运行状态。”。随后按 `Ctrl+3` 恢复 `http://127.0.0.1:8000` 并再次“保存设置”，按 `Ctrl+2` 回索引库、按 `F5` 验证恢复，最后按 `Ctrl+1` 返回搜索。
8. 预演与异常片段完成后，先在运行 Flutter 的终端按 `Ctrl+C`（或直接关闭应用）停止 Flutter，确认窗口退出；再回到启动 MVP 的终端按 `Ctrl+C` 停止预演实例，确认它退出并释放 8000 端口。不要删除 `rehearsal-01`，也不要同时运行两个实例或让它们争用 8000 端口。停止预演实例后再预检并启动正式实例；`recording-01` 必须保持全新，让正式录制从空白索引状态开始。

```powershell
& .\tools\start-mvp.ps1 -CheckOnly -DataDir 'F:\contentretrieval-demo\recording-01'
& .\tools\start-mvp.ps1 -DataDir 'F:\contentretrieval-demo\recording-01'
```

9. `recording-01` 启动后先检查 `http://127.0.0.1:8000/health/ready`，就绪后重新启动 Flutter，确保 controller 不沿用预演状态。

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/ready
Set-Location F:\contentretrivalsystem\frontend
flutter run -d windows
```

10. 新 Flutter 窗口出现后，按 `Ctrl+2` 到索引库并按 `F5`，明确确认真实 UI 显示“索引库为空”；再按 `Ctrl+1` 回到“搜索本地资料”首页，清空搜索框后开始正式录制。正式录制中的索引完成画面必须来自 `recording-01` 的真实任务；若任务耗时，不在镜头内连续等待。

## 五、异常预案

总原则：不伪装成功，不在镜头内等待超过 8 秒。耗时操作应保留开始动作，再跳切到真实完成状态；备用片段必须来自同一版本、同一批测试数据，并在画面上标明预录。

| 场景 | 触发 | 屏幕症状 | 立即动作 | 备用逐字话术 | 备用片段 |
| --- | --- | --- | --- | --- | --- |
| 服务离线 | 在 `rehearsal-01` 中把地址临时改为不可达端口 | 索引库显示“无法连接本地检索服务，请检查服务地址和运行状态。” | 保存错误地址后按 `Ctrl+2` 到索引库并按 `F5`；保留错误 3 秒。恢复 `http://127.0.0.1:8000` 并保存，再按 `Ctrl+2`、`F5` 验证，最后按 `Ctrl+1` | “界面如实报告本地服务不可达；我现在恢复地址并重新检查，不会把失败包装成结果。” | 插入 `rehearsal-01` 制作的离线与恢复连续片段。 |
| 索引慢 | 添加文件夹后 8 秒仍在处理 | 进度未完成、结果列表未刷新 | 8 秒处停录，等待真实完成后从相同构图续录 | “解析和建索引需要实际时间；这里跳切到同一次任务的真实完成状态。” | 使用本次录制数据目录的完成状态镜头。 |
| 部分失败 | 个别文件显示未处理或失败计数 | 完成面板存在失败详情 | 展开详情并如实展示；不要继续宣称五种均成功 | “本次任务有文件未处理，我保留失败证据，并改用录前已验证的完整批次继续说明。” | 同版本、同五文件的完整预演片段。 |
| 无结果 | 查询后为空 | 空结果提示，无目标文件 | 核对查询原文、模式、通道和内容类型；按 `F5` 后只重试一次 | “当前筛选下没有结果，我先核对条件；若仍为空，就把它记录为本次异常。” | 对应查询连续两次通过的预演片段，并标“预录”。 |
| 语义/图像排序波动 | 模型排序与预演不同 | 目标仍可见但名次变化，或滑出首屏 | 只在结果区正常滚动一次，确认目标是否可见 | “语义分值用于相对排序，名次可能波动；验收看目标是否出现在可见结果，不承诺第一名。” | 保留目标可见且未裁掉其他候选的片段。 |
| 源文件移动或打开失败 | 索引后移动文件，或默认程序不可用 | “打开文件”失败或系统无响应 | 保留提示；改为“复制路径”证明记录位置，不声称已打开 | “索引记录仍在，但源文件当前无法由系统打开；我保留失败提示并复制路径供排查。” | 录前已验证的成功打开片段，仅在文件恢复后使用。 |
| 无障碍布局不理想 | 150% 后控件换行或窗口过窄 | 文案截断、按钮需滚动或溢出 | 先将窗口恢复 1920×1080；仍异常则保留证据并停止该段 | “放大后的布局在当前窗口不理想，我不隐藏这个问题，改用完整画面展示可操作范围。” | 录前两次验证通过的 150% 全窗口片段。 |
| 成片超时 | 粗剪超过 5:00 | 时间线超出目标 | 优先压缩鼠标移动和重复停顿，不删失败说明与能力边界 | “这里保留关键证据，重复操作用短切压缩，结论不变。” | 使用 4:45–5:00 的固定总结片段。 |

## 六、录制验收清单

- [ ] 成片严格为 5:00，画面为 1920×1080、30 fps，声音清晰，鼠标可见，无通知或私密内容。
- [ ] 九个时间锚点顺序完整，讲解词可连读，所有文字与点击留有阅读停顿。
- [ ] 五个指定文件名均清晰出现；五条查询与三类查询流程均来自预演两遍的同一批数据。
- [ ] “搜索本地资料”“搜索资料”“添加资料文件夹”“资料已可搜索”等 UI 文案与当前版本一致。
- [ ] 精确、文本语义和图像语义结果均可见；图片只验收目标可见，不以固定第一名作为证据。
- [ ] 至少拍到一次筛选、一次“路径已复制”和一次“打开文件”的真实反馈。
- [ ] 高对比度、150% 文字、减少动态效果均保存成功，并用 `Ctrl+1` 返回搜索；字幕列出 `Ctrl+1`、`Ctrl+2`、`Ctrl+3`、`F5`。
