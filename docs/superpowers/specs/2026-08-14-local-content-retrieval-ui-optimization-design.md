# 本地内容检索 UI 优化设计

## 目标

把现有 Flutter Material 3 界面优化为以搜索为首要任务的桌面产品体验。用户打开应用后，应能立即描述自己记得的内容，在几秒内判断相关结果并打开原文件。

本轮设计采用“平衡研究台”作为整体结构，并吸收“聚光搜索台”的安静文案与渐进筛选。视觉北极星是“安静的研究案头”：搜索像桌面中央的一盏工作灯，相关资料和命中依据清晰浮现，系统基础设施退到背景。

## 用户与成功标准

主要用户是学生、研究人员，以及拥有大量本地学习或研究资料的知识工作者。次要用户是需要离线处理敏感本地文档的专业用户。产品同时服务依赖屏幕阅读器、键盘导航、高对比度或字体缩放的用户。

第一成功标准：用户不知道文件名和文件位置时，仅凭记得的大概内容也能快速找到目标资料。

第二成功标准：用户能稳定维护索引库，包括添加文件夹、查看进度、处理失败文件、重新索引和移除文件。

## 设计原则

1. 搜索先于管理。搜索是首屏唯一视觉主角，索引库和设置保持次级导航位置。
2. 结果值得信任。文件名、命中片段、来源位置和命中原因共同解释结果，不使用伪精确相关度百分比。
3. 技术隐于任务。界面使用用户语言，不在首页展示数据库、嵌入模型、CPU、延迟或存储体积等开发者指标。
4. 安静但不单调。通过相邻表面的明度与低色度差形成层次，不使用大面积纯色、装饰光晕或卡片墙。
5. 无障碍是基础。所有关键任务在键盘、屏幕阅读器、高对比度、200% 字体和减少动态效果下保持完整可用。

## 信息架构与布局

### 应用外壳

`AppShell` 保留“搜索、索引库、设置”三个主目的地。宽度不小于 1000px 时，左侧导航显示品牌名称和文字标签；小于该断点时折叠为 72px 图标轨道，保留工具提示与可访问名称。

左侧导航底部只允许显示用户可理解的索引可用性摘要，例如“本地资料已准备就绪”。不得显示 Chroma DB、embedding 或模型运行指标。

主工作区顶部使用轻量工具栏，左侧显示当前页面标题，右侧显示“服务可用、正在检测、离线”等后端状态。在线状态采用紧凑文字与图标，不占据整条高强调横幅；离线和错误状态根据严重性提升可见度。

### 搜索页

宽屏采用三栏结构：左侧应用导航、中央搜索与结果区、右侧常驻筛选栏。搜索页内部宽度不小于 1100px 时常驻筛选栏；低于该断点时隐藏筛选栏，改为带有效筛选数量的“筛选”按钮。

搜索舞台位于中央区顶部，包含：

- 标题：“找回你记得的内容”。
- 说明：“描述一个概念、一段话，或图片中的内容。”
- 可见输入标签“搜索内容”。
- 搜索输入、弱化的 `Ctrl+K` 提示和“搜索”主按钮。
- 当前检索方式和内容类型的紧凑摘要。

结果区紧接搜索舞台。结果使用连续列表与分隔线，不把每条资料包裹成独立悬浮卡片。每条结果的阅读顺序固定为：

1. 文件类型与文件名。
2. 命中片段。
3. 页码、段落、资料位置等来源信息。
4. 来自后端 `match_reasons` 的命中原因。
5. 打开文件和复制路径操作。

### 索引库

索引库沿用统一页面标题和工具栏。添加文件夹是本页主操作；刷新是次级操作。索引任务只在任务存在时显示为临时状态区。

文件列表使用与搜索结果一致的连续列表语言，减少卡片堆叠。文件名、路径、类型、大小、记录数和修改时间保持可扫描；打开、复制、重新索引和移除操作使用一致的按钮层级。

### 设置

设置页保持约 760px 的舒适阅读宽度。页面分为“后端连接”和“外观与无障碍”两个轻量分层区块，不使用明显悬浮大卡片。

主题、高对比度、文字大小和减少动态效果保持现有真实能力。“保存设置”为主操作，“恢复默认设置”为次级操作；200% 字号时操作区允许换行，不固定覆盖内容。

## 视觉系统

### 颜色

现有 `#3659AD` 定义为“研究钴蓝”，继续作为 Material 3 种子色。它只用于主要操作、当前导航、选中筛选和键盘焦点。

工作区使用 `surface`，左侧导航、状态栏、搜索舞台和筛选栏使用相邻的 `surfaceContainer` 角色形成轻量分层。不同表面必须有可感知但克制的明度或低色度差，避免完全单调纯色。

成功、警告和错误色只表达真实状态，并始终伴随图标或文字。正文与背景达到 4.5:1，对大文字和必要图形达到 3:1；占位文字同样达到 4.5:1。

### 排版

继续使用跨平台系统无衬线字体和 Material Icons，不引入网络字体或第二套图标体系。

- 页面标题：28px，常规字重。
- 主要区块标题：22px，常规字重。
- 正文与命中片段：14px，适当行高。
- 按钮、导航和筛选标签：14px，半粗字重。

连续说明文字限制在约 65–75ch。页面标题和重要区块使用语义 header，不使用全大写正文或展示字体。

### 形状与层次

输入、按钮、筛选器和结果文件类型标识使用 12px 圆角；导航选中指示器使用 14px 圆角。主要按钮最小高度 48px。

系统默认依靠 tonal surfaces、分隔线和留白表达层次。阴影只用于聚焦搜索、临时浮层、对话框和确实离开基础平面的状态。同一元素不得同时叠加装饰性一像素边界和宽模糊阴影。

### 动效

悬停、按压和选择反馈使用 150ms 左右的快速过渡；面板和状态切换不超过 220ms，使用平滑 ease-out 曲线。不得增加编排式页面入场。减少动态效果启用时，非必要过渡变为即时状态切换。

## 组件与状态

### 搜索输入

搜索输入约 56px 高，在页面中获得最高视觉优先级。默认状态依靠填充表面和清晰边界；聚焦时使用研究钴蓝双倍描边与轻微抬升。输入始终有可见标签，不能只依赖占位文字。

### 筛选

宽屏常驻筛选保留“精确、混合、语义”、检索通道和内容类型。窄屏通过侧栏或底部面板渐进展开，关闭后完整保留用户选择。

“筛选”按钮显示有效筛选数量，但计数不是唯一状态提示。至少保留一个检索通道的现有约束继续成立；违反约束时在筛选区内联说明。

### 结果

结果条目默认平坦，悬停时只改变相邻表面色。键盘焦点必须清晰包围当前条目或其操作。文件路径允许视觉截断，但必须能通过工具提示、语义信息或复制操作获得完整值。

### 初始、加载、空结果与错误

- 初始状态：显示搜索示例与支持内容范围，不显示虚构结果。
- 加载状态：保留查询与筛选，显示与真实结果结构一致的骨架。
- 空结果：重述查询和有效筛选，提供“清除筛选”，不自动扩大范围或发起第二次请求。
- 搜索错误：保留查询和筛选，在结果区显示安全文案与“重新搜索”。
- 后端离线：禁用新搜索，保留已有结果和文件操作，并提供“重新检测”。
- 索引失败：在任务或文件行内显示原因和可执行的下一步，不暴露堆栈。
- 设置保存失败：保留草稿，在设置区顶部显示错误；保存成功通过 live region 与可见反馈共同确认。

## 数据流与代码边界

本轮不改变后端 API、搜索请求字段、设置持久化格式或 controller 的职责。

`AppShell` 继续负责导航选择、已访问页面和响应式断点。`SearchController`、`IndexLibraryController`、`SettingsController` 与 `BackendStatusController` 继续持有业务状态。页面和展示组件只订阅状态并触发公开操作，不直接构造网络请求。

搜索由 Enter 或“搜索”按钮触发。空查询不发送请求。已有非空查询时，修改检索模式、通道或内容类型可以按现有规则重新提交。晚到响应、错误映射、文件打开和路径复制继续沿用当前实现。

为降低单文件复杂度，可在实施时抽取纯展示组件，例如页面工具栏、搜索舞台、后端状态指示器和连续资料列表，但不得引入新的全局状态管理框架。

## 无障碍与响应式

保持 WCAG 2.1 AA，并保留：

- 完整键盘导航与 `Ctrl+1/2/3`、`Ctrl+K`、F5 等现有快捷键。
- 可见焦点和符合阅读顺序的焦点遍历。
- 屏幕阅读器的页面标题、状态 live region、表单标签和操作名称。
- 高对比度亮色与暗色方案。
- 100%、125%、150%、200% 字体缩放。
- 减少动态效果。
- 不小于 48px 的主要触控目标。

响应式重点覆盖：

- 1440×900：完整三栏。
- 1280×720：完整任务流程，无横向溢出。
- 1000–1099px：展开导航与收起筛选之间的过渡状态。
- 小于 1000px：紧凑导航轨道与渐进筛选。
- 200% 字号：搜索操作、设置操作与结果元数据允许换行和纵向重排。

## 测试与验收

### 自动化验证

执行：

```powershell
cd frontend
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
```

更新或增加以下 Widget 与无障碍回归：

- 宽屏显示常驻筛选，窄屏显示带计数的筛选入口。
- 搜索输入在初始阅读顺序和焦点顺序中优先。
- 在线、检测中、离线、加载、成功、空结果和错误状态可见且语义正确。
- 结果条目包含文件名、命中片段、来源位置、命中原因和操作。
- 索引库与设置页在 200% 字号下无关键内容截断。
- 高对比度与减少动态效果设置继续生效。
- 主要交互目标不小于 48px。

### 视觉验收

在实际 Flutter 应用中检查亮色、暗色、高对比度和 200% 字号。至少覆盖搜索初始态、加载态、结果态、空结果、离线态、索引库列表、索引任务和设置页。

通过标准：

- 首屏注意力首先落到搜索，不落到导航、状态或索引指标。
- 相邻表面层次可感知，但无大面积高饱和色、卡片墙或装饰阴影。
- 结果的命中依据和来源信息比操作按钮更先被读取。
- 所有关键状态在不依赖颜色时仍可理解。
- 1280×720、1440×900 和 200% 字号下没有横向溢出或不可达操作。

## 非目标

本轮不新增搜索历史、推荐结果、收藏、文件预览、权重调节、时间范围、开发者监控面板或新的索引能力。也不修改后端检索算法、API 契约、数据库结构或设置存储格式。
