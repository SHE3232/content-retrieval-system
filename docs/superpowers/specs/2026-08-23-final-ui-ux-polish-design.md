# 最终 UI/UX 打磨设计

日期：2026-08-23  
状态：已确认，等待实施计划

## 1. 背景

本轮对 Flutter 客户端做最终 UI/UX 深度重整。目标是统一搜索、索引库和设置三页的文案、状态、布局与交互，修复小型体验缺陷，同时保留既有功能、后端契约、数据模型和无障碍能力。

主要验收场景是 Windows 桌面端。窄窗口、深色主题、高对比度、键盘操作、屏幕阅读器语义、减少动态效果和 200% 字号不得退化。

## 2. 目标与非目标

### 目标

- 建立三页共用的任务工作台骨架。
- 消除重复标题、冲突文案、漂移的间距和不一致的反馈位置。
- 让搜索保持产品主任务，索引维护和设置保持清晰但次要。
- 统一初始、加载、成功、空、错误和禁用状态。
- 保留并加强键盘、屏幕阅读器、高对比度和大字号体验。
- 通过现有 controller 和 API client 完成改造，不引入新的业务状态源。

### 非目标

- 不修改 FastAPI 接口、请求字段、响应字段或数据模型。
- 不新增搜索、索引或设置能力。
- 不改变索引和检索算法。
- 不引入新的导航目的地、品牌字体或装饰性视觉主题。
- 不把客户端改造成技术后台或指标仪表盘。

## 3. 设计方向

采用已确认的 A 方案“任务工作台”。

搜索页由主要任务、连续结果和上下文筛选组成；索引库由资料清单和就地任务状态组成；设置页使用清晰的分组表单。三页共享相同的导航、页头、状态与反馈规则。

核心原则：

1. 每页只有一个一级标题，避免“搜索”与“找回你记得的内容”重复表达同一层级。
2. 每页只有一个主要动作：搜索资料、添加资料文件夹或保存设置。
3. 连接、任务、成功和错误状态有固定位置与固定语义。
4. 宽屏利用上下文侧栏，窄窗口和大字号改为单列或模态面板。
5. 结果与文件清单使用连续列表，不堆叠同构卡片。

## 4. 共用页面骨架

### 导航

- 保留“搜索、索引库、设置”的顺序和 `Ctrl+1/2/3` 快捷键。
- 宽窗口显示品牌文字和导航标签，空间不足时收为图标轨道并提供不重复朗读的 Tooltip。
- 当前目的地同时通过容器、图标状态和语义选择状态表达，不能只依赖颜色。

### 页头

页头统一包含：

- 单一页面标题。
- 一句不重复标题的任务说明。
- 可选的上下文状态或主要操作。

搜索页显示本地检索服务状态；索引库显示“添加资料文件夹”；设置页不放置无关状态或额外操作。

### 状态与反馈

- 全局连接状态固定在搜索页页头，使用图标和文字表达。
- 页面任务状态位于主要内容顶部，不使用漂移位置的横幅堆叠。
- 临时成功反馈使用 SnackBar，并通过 live region 在事件边界播报。
- 需要用户处理的错误使用持久反馈区域，提供明确的“重新尝试”操作。
- 同一事件不同时使用横幅、SnackBar 和重复语义播报。

## 5. 搜索页

### 结构

1. 页头：“搜索本地资料”与“描述你记得的内容，找到对应文件和位置”。
2. 搜索输入与主要按钮“搜索资料”。
3. 结果摘要，包括结果数量和排序说明。
4. 连续结果列表。
5. 宽屏右侧的“筛选结果”上下文面板；窄屏或大字号下改为模态筛选面板。

### 搜索结果

每项按以下顺序呈现：

1. 文件名。
2. 命中片段。
3. 命中原因与来源位置。
4. 打开文件、复制路径等操作。

不显示伪精确的相关度百分比。文件名和路径可按布局换行或视觉截断，但完整值必须可被辅助技术读取并可复制。

### 状态

- 初始：提供简短示例和操作引导，不重复搜索页标题。
- 加载：显示“正在搜索资料”，保留搜索输入和当前条件。
- 更新：筛选变化后显示“正在更新结果”，保留旧结果直到新结果到达，不移动焦点。
- 结果：显示结果数量、排序说明和连续列表。
- 空：说明“没有找到相关资料”，提供调整搜索内容或重置筛选的动作。
- 失败：使用用户语言区分服务不可用、请求超时、无效响应和搜索条件错误，并提供对应操作。

## 6. 索引库

### 结构

1. 页头：“索引库”与“管理可搜索的本地资料”。
2. 主要按钮“添加资料文件夹”。
3. 文件总数、可搜索数量和需要处理数量组成的紧凑摘要。
4. 单一索引任务进度区域。
5. 连续文件列表和分页。

### 文件与任务交互

- 每个文件显示名称、类型、更新时间和可用状态。
- 高频操作“打开文件”直接可见；重新索引、移除等次要或危险操作收进“更多操作”。
- 索引任务显示资料夹、已处理数量、总数和失败数量。
- 失败详情使用用户可理解的文件、阶段和处理建议，不要求用户理解内部错误码。
- 重新索引和移除确认框明确说明对象与影响；完成后焦点返回原列表位置或最接近的稳定位置。

## 7. 设置页

### 结构

设置表单使用单一内容列，不使用嵌套卡片。分组为：

1. 连接。
2. 外观。
3. 无障碍。

底部操作区显示“已保存”或“尚未保存更改”，并提供“恢复默认设置”和主要按钮“保存设置”。

### 行为

- 后端地址在用户文案中称为“服务地址”，辅助说明为“用于连接这台设备上的检索服务”。
- 保存失败时保留草稿和焦点位置。
- 恢复默认设置必须确认，避免误触清空用户偏好。
- 保存、重置和恢复损坏设置的结果只播报一次。
- 主题、文字大小、高对比度和减少动态效果继续使用现有数据模型与立即预览行为。

## 8. 文案规范

界面使用普通用户语言，不出现“后端、向量、embedding、Chroma”等实现术语。

统一词汇：

| 语义 | 统一文案 |
|---|---|
| 本机 API 服务 | 本地检索服务 |
| 后端地址 | 服务地址 |
| 执行搜索 | 搜索资料 |
| 添加索引目录 | 添加资料文件夹 |
| Hybrid 模式 | 综合 |
| 重试当前任务 | 重新尝试 |
| 删除索引记录 | 从索引库移除 |

按钮采用“动作 + 对象”。关闭、取消等标准对话框操作可保留简短标签。省略号只表示操作会继续打开对话框或面板；进行中状态使用中文省略号“…”且不改变按钮宽度导致布局跳动。

## 9. 交互与数据流

业务数据流保持不变：

`用户操作 → 现有 controller → 现有 API client → controller 状态 → 页面状态展示组件`

统一状态展示组件只负责文案、布局、视觉和语义，不发起请求，不复制 controller 状态，不改变 API 契约。

交互规则：

- 保留 `Ctrl+K`、`Ctrl+1/2/3` 和 `F5`。
- `Esc` 优先关闭当前浮层，再处理输入框失焦。
- 筛选变化在已有查询存在且服务可用时自动更新结果。
- 加载期间禁用会产生冲突请求的操作，但保留可读标签和当前状态。
- 对话框或筛选面板关闭后，焦点返回触发控件。
- 页面切换不丢失已访问页面的搜索、列表和草稿状态。

## 10. 错误处理

- 搜索校验错误与输入框关联，并给出可执行的修正提示。
- 服务不可用时保留用户输入，禁用提交并提供检查服务或刷新状态的路径。
- 请求超时允许重新尝试，不清空查询和筛选。
- 无效响应使用普通用户语言，不显示堆栈、内部路径或敏感内容。
- 索引任务部分失败时显示已完成数量和失败数量，不把部分成功误报为完全失败。
- 设置保存失败时保留未保存状态和草稿。

## 11. 响应式与视觉规则

- Windows 宽屏为主要布局；NavigationRail 在空间不足时收为图标轨道。
- 筛选侧栏只在内容区有足够宽度且当前字号允许时常驻。
- 窄窗口和 200% 字号采用单列，操作区使用 Wrap 或纵向排列。
- 主要交互目标不小于 48×48。
- 沿用 Material 3、研究钴蓝和现有高对比度配色。
- 内容层级主要依靠表面明度、留白、排版和分隔线，不同时使用宽阴影与边框。
- 主要容器圆角保持 12–16px，不新增玻璃拟态、渐变文字或装饰性动效。

## 12. 无障碍要求

- 每页只暴露一个一级语义标题。
- 品牌、图标、Tooltip 和可见标签不得产生重复朗读。
- 焦点顺序为“导航 → 页头操作 → 主要任务 → 内容 → 次要操作”。
- 加载开始、完成、错误和保存结果在事件边界播报；筛选逐项变化不打断屏幕阅读器。
- 所有颜色状态同时提供文字或图标。
- 路径、文件名、错误和状态的完整文本可被辅助技术访问。
- 高对比度模式保持明确边界和至少 WCAG 2.1 AA 对比度。
- 200% 字号下不截断关键操作、状态或命中说明。
- 减少动态效果启用时，新增过渡立即完成或仅使用不影响理解的瞬时变化。

## 13. 组件边界

优先复用和调整以下现有组件：

- `AppShell`：导航、页面保持和全局快捷键。
- `WorkspaceHeader`：统一页头结构。
- `SearchStage`：搜索输入与主要动作。
- `SearchFilterPanel`：宽屏侧栏与窄屏模态共用内容。
- `SearchStateView`：搜索状态容器。
- `IndexJobPanel`：索引任务状态。
- `IndexedFileTile` 与 `SearchResultTile`：连续列表项。
- 设置页分组组件：从卡片容器调整为分隔式表单区块。

如需新增共用组件，限定为纯展示和交互基础设施，例如统一反馈区域或状态摘要；不得把业务请求逻辑移入共用组件。

## 14. 验收与测试

### 自动化验证

- 运行 `dart format`。
- 运行 `flutter analyze`。
- 运行完整 `flutter test`。
- 更新既有 widget、语义、键盘、高对比度和页面测试。
- 补充初始、加载、成功、空、错误和禁用状态测试。
- 补充文案一致性、焦点返回、快捷键、窄窗口和 200% 字号测试。

### 手工验收

- Windows 桌面端逐页检查浅色、深色和高对比度。
- 仅用键盘完成搜索、筛选、打开结果、索引管理和保存设置。
- 使用 200% 字号检查单列重排、按钮换行和完整文本。
- 检查屏幕阅读器的标题、导航选择、状态和结果朗读顺序。
- 检查减少动态效果下没有依赖动画才能理解的状态。

## 15. 完成标准

- 三页使用一致的导航、页头、间距、状态和操作层级。
- 用户界面不再暴露实现术语或出现同义文案漂移。
- 搜索、索引和设置的全部核心状态有明确、稳定且可访问的呈现。
- 现有后端契约、功能范围和 controller 数据流保持不变。
- `flutter analyze` 与完整 `flutter test` 通过。
- Windows 桌面端以及窄窗口、深色、高对比度、键盘和 200% 字号验收通过。
