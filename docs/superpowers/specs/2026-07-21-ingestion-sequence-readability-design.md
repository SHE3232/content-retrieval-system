# 导入时序图可读性改版设计

## 目标

修复 `docs/week2/reports/01_系统架构设计.docx` 中“当前任务创建、解析与查询时序”图的可读性问题。保持原有业务语义和黑白文档规范，不改变 API、状态或执行顺序。

## 问题

- “当前行为”注释框覆盖 `resolve / parse`、`ParseResult / ParseError` 等消息线和标签。
- 消息标签与泳道线距离过近，局部文字相互争抢视觉空间。
- 注释文字字号偏小，在 Word 页面宽度内缩放后难以快速阅读。

## 已批准方案

采用方案 A：

1. 删除时序区内部的浮动“当前行为”注释框。
2. 把三条行为说明移到时序图底部的独立说明带，与泳道和消息箭头完全分离。
3. 增大关键消息标签和说明文字字号，并适当增加泳道横向间距。
4. 为消息标签保留白色留白区，避免文字压在线条上。
5. 保留原有参与者、消息顺序、状态名和返回类型，不新增业务流程。

## 视觉约束

- 字体：Times New Roman；中文由 Word/系统按字形回退显示。
- 文字与线条：黑色。
- 背景：白色。
- 图在 DOCX 中仍作为高分辨率内联图片插入，宽度不超过正文可用宽度。
- 图注、替代文本和图编号保持不变。

## 验收标准

- 注释说明不与任何泳道、箭头或消息标签重叠。
- `asyncio.to_thread(parse_paths)`、`resolve / parse`、`ParseResult / ParseError`、`BatchResult` 在 100% 页面视图下清晰可辨。
- 图内不存在裁切、重叠或贴边文字。
- Word 能打开并导出文档；最终页数、目录、图注和正文结构正常。
- 最终 DOCX 继续满足 Times New Roman、黑色文字与线条、白色背景的项目规范。

## 修改范围

- 修改 `tmp/docx/build_week2_reports.py` 中时序图绘制布局。
- 重新生成 `docs/week2/reports/01_系统架构设计.docx` 及对应时序图资源。
- 不修改后端代码、API 文档、测试报告和周报内容。
