# 第八周结项与干净工程交付设计

## 1. 背景与结论

第八周不再扩展普通产品功能，而是把前七周成果收束为可追溯、可运行、可公开、可展示、可审计的最终交付。当前 Git 基线为 `9b6718da31952f75e50c1b415ca9f6ffc0206b60`，在隔离工作区重新验证得到 Python 主套件 464 项通过、1 项跳过，启动/打包/合规 124 项通过，演示 33 项通过，Flutter 249 项通过，合计 870 项通过、1 项跳过，`flutter analyze` 为 0 issue。

最终采用“保留原始仓库、隔离精简、双轨发行、统一提交号”的方案：公开源码和默认可分发包排除受限模型权重；课程演示研究包可以包含 MobileCLIP-S0 权重，但必须明确标记为仅限非商业研究。结项报告、作品集、演示视频、平台构建、GitHub Release 和所有哈希清单必须引用同一个最终源码提交。

## 2. 目标与非目标

### 2.1 必须实现的目标

1. 冻结唯一的 Week 8 最终提交，并从干净工作树完成全量测试、平台构建、归档与只读复核。
2. 形成 Windows、Linux、macOS 三个平台的生产发布候选及真实环境证据；Windows 和 Linux 在现有主机与 WSL 完成，macOS 必须在真实 Mac 完成构建与 VoiceOver 验收。
3. 建立公开 GitHub 仓库，具备完整 README、许可证材料、贡献指南、CI、版本标签、Release Notes 和可下载产物。
4. 形成公开源码包、默认公开发行包和课程演示研究包三种边界清晰的交付物。
5. 按九段式脚本完成两轮预演和严格 5:00、1920×1080、30 fps 的成片。
6. 形成完整作品集、第八周工作周报和不少于 8000 字的中文图文结项报告。
7. 形成独立干净工程目录，删除有充分证据证明无用的代码、变量、函数与重复实现，排除缓存、临时目录、历史构建物、用户数据和受限内容，同时保留关键代码、必要注释、测试、构建、演示、合规和维护能力。

### 2.2 非目标

1. 不在第八周引入新的检索模型、数据库、UI 框架或产品功能。
2. 不为了减少文件数量而删除可复现测试、许可证证据、构建脚本或关键设计说明。
3. 不修改或清理原始主工作区中的用户未提交改动；原始仓库继续作为可恢复基线。
4. 不把缺少真实环境证据的平台标记为通过，不把研究用途模型包宣传为通用开源或商业发行包。

## 5. 双轨发行与开源边界

### 5.1 公开源码工程

公开工程保留 `backend`、`frontend`、必要的 `tools`、可复现测试、演示数据生成器、技术文档、锁文件和许可证材料。它排除模型权重、下载数据二进制、用户文件、运行数据库、虚拟环境、构建缓存、历史提交 ZIP、临时 QA 目录和本机凭据。

### 5.2 默认公开发行包

默认公开发行包只包含许可证允许再分发的 CPU 运行时、Tika、前后端程序和许可证归档。它不包含 MobileCLIP-S0 权重；图像语义功能通过用户自行提供合规权重或未来替代模型启用。界面和文档必须明确说明该边界，不能静默失败。

### 5.3 课程演示研究包

研究包可保留 MobileCLIP-S0 权重，以满足完整五格式、多模态演示。包清单必须标记 `research-only`，随附 Apple Machine Learning Research Model License、模型卡、来源修订和哈希，并明确禁止把该包描述为无限制开源或商业发行。

## 6. 代码与目录精简方法

精简分为“发行目录白名单”和“源码级死代码清理”两层。

第一层不改产品逻辑：公开目录仅复制明确需要的源码、测试、构建、演示、合规和文档路径。当前已识别的仓库级排除候选包括 `.codex_tmp`、`.tmp*`、`output`、`outputs`、运行数据、虚拟环境、历史解压目录、周提交重复 ZIP 和本机模型权重。

第二层修改源码：

1. Python 引入 Ruff 或等价静态检查，覆盖未使用导入、变量和明显不可达代码。
2. Flutter 继续以 `flutter analyze` 为主；当前基线 0 issue。
3. 对“仅定义一次”的符号执行装饰器、反射、框架回调和序列化约定复核。FastAPI 路由处理器与 Pydantic 校验器虽然文本引用次数低，但由框架调用，不能据此删除。
4. 每个删除批次先增加或确认覆盖该行为的测试，再删除最小范围，随后运行对应专项和全量回归。
5. 保留解释公共接口、线程/一致性、安全边界、许可证边界和非直观算法的注释；删除只复述代码、已经失效或误导维护者的注释。

删除必须发生在隔离分支且形成独立提交。任何无法通过引用分析、测试、运行路径或发布白名单证明无用的内容均保留。
