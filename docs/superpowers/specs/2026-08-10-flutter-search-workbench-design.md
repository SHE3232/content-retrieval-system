# Flutter 搜索工作台设计

## 目标

在现有 `frontend/` Flutter 桌面脚手架中实现一个可连接本地 FastAPI 的
Material 3 应用框架与搜索页。首版覆盖导航、后端状态、搜索输入、检索通道与
内容格式过滤、结果列表、文件打开，以及加载、空结果、断连和搜索错误状态。

首版导航包含“搜索”“索引库”“设置”。搜索页完整可用，索引库和设置页保留
成型入口与明确占位，不在本次实现索引管理或偏好保存。

## 已确认范围

- 使用现有 Flutter 3.44.6、Dart 3.12.2 桌面工程。
- 默认连接 `http://127.0.0.1:8000`。
- 应用启动后自动检查后端就绪状态，并支持手动重新检测。
- 搜索、过滤和结果数据均使用真实后端接口，不使用本地模拟数据作为运行时回退。
- 点击结果使用系统默认应用打开本地文件，并提供复制路径入口。
- 当前视觉 V2 作为首版基线；更强品牌化、复杂动效和进一步视觉实验延后。

## 设计判断

这是面向本地内容检索用户的桌面工具，不是营销页。设计语言采用沉静、精确、
高扫描效率的 Material 3 产品界面。

- `DESIGN_VARIANCE: 6`：布局有清晰层次，但不使用实验性结构。
- `MOTION_INTENSITY: 4`：仅使用表达层级、操作反馈和状态变化的轻量动效。
- `VISUAL_DENSITY: 6`：充分利用桌面空间，同时保证结果片段可快速阅读。
- 唯一设计系统为 Flutter Material 3，不混用其他组件体系。

## 信息架构

### 应用框架

宽窗口使用三栏结构：

1. 左侧 Material 3 导航区域，显示品牌、搜索、索引库和设置入口。
2. 中央搜索工作区，包含搜索舞台、快速过滤和结果列表。
3. 右侧过滤面板，包含检索方式、参与通道和内容格式。

窗口宽度不足时，导航折叠为窄导航轨道，右侧过滤面板改由筛选按钮打开。首版以
Windows 桌面窗口为主要验收环境，同时保持 Flutter 的 macOS、Linux 工程可分析。

### 页面

- 搜索：完整实现。
- 索引库：显示“功能将在后续版本提供”的占位页，保留导航选中状态。
- 设置：显示后端地址、主题等后续配置方向的占位页，不允许编辑或持久化。

## 视觉系统

### 颜色

采用冷灰中性色和单一钴蓝强调色。绿色和红色只用于真实在线、成功和错误语义，
不作为装饰色。亮色与暗色均通过语义化 `ColorScheme` 定义，并默认跟随系统主题。

### 形状与层次

- 页面和主要容器使用 16 像素级软圆角。
- 输入、按钮和导航项使用 10 至 12 像素圆角。
- 筛选标签使用全圆角。
- 阴影只用于应用外壳、聚焦搜索框和临时浮层；结果列表主要依靠间距、背景状态和
  分隔线表达层次。

### 字体与图标

- 使用系统字体和 Flutter Material Icons，不引入网络字体或第二套图标家族。
- 文件类型使用紧凑文字标识，例如 PDF、DOCX、IMG。
- 数值使用等宽数字特性，业务文字保持系统无衬线字体。

### 动效

- 控件悬停与按压反馈为 120 至 180 毫秒。
- 搜索结果进入使用轻量透明度和纵向位移动效，总时长不超过 320 毫秒。
- 筛选变化采用 Material 3 状态层和布局过渡。
- 系统要求减少动态效果时，关闭自动进入动画，仅保留即时状态变化。

## 组件边界

### `AppShell`

负责主题、当前导航目的地和宽度适配。它只组合页面，不包含搜索网络逻辑。

### `BackendStatusController`

负责就绪检查、轮询、手动重试和状态暴露。状态至少包括：

- `checking`
- `online`
- `offline`

应用启动时立即请求 `/health/ready`。成功后每 10 秒复查；失败后保持离线状态，
允许用户手动重新检测。页面销毁时停止定时器和未完成请求。

### `SearchController`

持有查询文本、筛选值、请求状态、结果和最近一次错误。它负责请求防重入、忽略过期
响应以及把接口错误转换为稳定的界面状态。

搜索仅由以下操作触发：

- 点击“搜索”。
- 输入框按 Enter。
- 已有查询时修改检索方式或过滤项。

空白查询不发送网络请求，输入框下方显示内联校验信息。

### `SearchApiClient`

负责 JSON 编解码和 HTTP 状态映射。界面组件不直接拼接 URL 或读取原始响应。

### `SearchStage`

包含标题、输入标签、搜索框、快捷键提示、搜索按钮和快速过滤。输入必须有可见标签，
不能仅依赖占位文字。

### `SearchFilterPanel`

负责检索方式、参与通道和内容类型选择。至少保留一个检索通道；如果用户尝试清空
所有通道，最后一个选项保持选中并显示简短说明。

### `SearchResultList`

根据状态显示骨架、结果、空状态或错误状态。每个 `SearchResultTile` 展示：

- 文件类型和文件名。
- 命中片段。
- 页码或段落号，存在时才显示。
- 命中通道。
- 截断后的本地路径。
- “打开”操作和复制完整路径操作。

## 后端契约映射

### 就绪检查

```text
GET /health/ready
```

- `200`：后端在线。
- 非 `200`、超时或连接失败：后端离线。

### 索引统计

```text
GET /v1/index/stats
```

响应字段：

- `record_count`
- `file_count`
- `text_record_count`
- `image_record_count`

统计加载成功时在导航底部展示；失败不会阻塞搜索，只隐藏统计并保留后端状态。

### 搜索

```text
POST /v1/search
```

默认 `top_k` 为 20。请求字段映射如下：

- `query`：规范化后的输入文本。
- `channels`：界面选中的后端通道。
- `filters.modalities`：`text`、`image`。
- `filters.mime_types`：由格式过滤映射出的 MIME 类型。
- `weights`：首版不由用户编辑，传 `null`，使用后端默认融合权重。

检索方式映射：

- 精确：`keyword`。
- 混合：`keyword`、`text_semantic`、`image_semantic`。
- 语义：`text_semantic`、`image_semantic`。

内容类型映射：

- 文档：PDF、DOCX 等文档 MIME 类型。
- 文字文件：`text/plain` 及后端已支持的文本 MIME 类型。
- 图片：后端已支持的 `image/*` MIME 类型集合。

如果后端实际索引格式集合与上述分组不同，客户端只发送后端明确支持的 MIME 类型，
不在客户端伪造格式支持。

搜索响应字段映射：

- `hits` 转换为结果列表。
- `total_candidates` 用于结果摘要。
- `elapsed_ms` 仅显示真实后端值。
- `match_reasons` 转换为命中原因标签。
- `score` 保留在模型中，首版不显示假精度百分比。

## 文件打开与路径复制

打开操作使用平台默认应用处理结果中的绝对文件路径。执行前检查路径存在且是文件：

- 成功提交给系统后不显示成功提示。
- 文件不存在时在对应结果行显示“文件不存在”。
- 系统拒绝或没有关联应用时显示可重试的内联错误。

复制路径使用系统剪贴板，完成后显示短暂的 Material 3 `SnackBar`。文件路径仅来自后端
结果，不接受用户输入的命令或参数，不通过 Shell 字符串拼接执行。

## 状态设计

### 初始状态

显示搜索输入和简短说明，不展示虚构结果。后端离线时仍可输入，但搜索按钮不可用，
同时提供“重新检测”。

### 加载状态

保留搜索和过滤条件，结果区域显示与最终结果行结构一致的骨架。重复搜索期间禁用搜索
按钮，避免并发重复请求。

### 空结果

显示查询词和当前过滤摘要，并提供“清除过滤”操作。不会自动扩大检索范围或发送第二次
请求。

### 搜索错误

在结果区域显示稳定错误信息和“重试”操作，保留查询与筛选。`422` 映射为请求校验
错误，`503` 映射为服务不可用，其余失败使用通用搜索错误文案。

### 后端断连

顶部状态变为离线，搜索按钮不可用，当前成功结果可以继续查看和打开。离线不会清空
已有结果。

## 可访问性与键盘操作

- 所有输入都有可见标签和语义描述。
- Material 3 状态层不能成为唯一状态提示；在线、离线和错误均有文字。
- 正文和控件满足 WCAG AA 对比度。
- Tab 顺序为导航、搜索输入、搜索按钮、快速过滤、结果操作、详细过滤。
- Enter 执行搜索，`Ctrl+K` 聚焦搜索框，Escape 清除搜索框焦点但不清空内容。
- 结果标题、路径和操作按钮为独立可聚焦元素。

## 错误处理与安全边界

- 所有请求设置有限超时，不允许界面永久停留在加载状态。
- 新搜索开始时保留请求序号，晚到的旧响应不得覆盖新结果。
- HTTP 错误正文只读取后端公开的 `detail.code` 和 `detail.message`，不展示堆栈或内部
  路径诊断。
- 打开文件不执行 Shell 命令字符串，不把查询内容传给系统命令。
- 前端不启动、停止或管理后端进程，仅检测连接状态。

## 测试与验收

### 单元测试

- 搜索请求 JSON 和三种检索方式映射正确。
- 内容类型映射只生成支持的 MIME 类型。
- 搜索响应和结构化错误解析正确。
- 过期响应不会覆盖较新的搜索结果。
- 后端状态轮询可启动、重试并在销毁时停止。
- 文件不存在或平台打开失败时返回稳定界面错误。

### Widget 测试

- 三个导航目的地可切换，搜索页为默认页。
- 在线、检查中和离线状态可见且有文字说明。
- 空白查询不发送请求。
- Enter、搜索按钮和筛选变化按规则触发搜索。
- 加载、成功、空结果、搜索错误和断连状态均可渲染。
- 结果行包含文件名、片段、路径、命中原因和打开操作。
- 窄窗口隐藏右侧面板，并保留可访问的筛选入口。

### 视觉验收

- 亮色和暗色主题均无纯黑纯白大面积平面，层级清晰。
- 页面只使用一套 Material 3 组件和图标语义。
- 导航、按钮和输入标签在桌面宽度下不换行。
- 结果列表在 1280×720 和 1440×900 窗口内可读，无横向溢出。
- 减少动态效果开启时没有自动进入动画。
